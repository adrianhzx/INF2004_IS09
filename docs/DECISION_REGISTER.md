# Decision register - Rev B open review points (Version C, NOT adopted)

Status vocabulary: `ACCEPT` (implemented as a minimal fix needed to honour an
existing FR/NFR or physical safety; team ratification still requested),
`DEFER`, `REJECT`, `NEEDS TEAM INPUT`. Nothing here changes task ownership,
priorities, S0-S7, the SafeStop contract or any adopted field width.

| ID | Open point (Rev B p.1 "Open review points") | Reproducible consequence | Safety impact | Minimal patch | Required by | Status |
|---|---|---|---|---|---|---|
| D-01 | Remote STOP path: does TelemetryCommsTask call `SafeStop_Request(REMOTE_STOP)`? REMOTE_STOP is not a stop cause. | A validated MQTT STOP has nowhere to go; FR23 "accept STOP" would be unmet or would misuse another cause code. | A remote STOP that silently does nothing is a safety finding; a remote STOP that auto-latches via a generic network bit would violate "WIFI_LOSS never stops the car". | `app_data.h` reserves stop-cause code 11 `APP_STOP_CAUSE_REMOTE_STOP` behind `APP_ADOPT_REMOTE_STOP_CAUSE` (default 0). With it 0, a validated remote STOP is delivered to VehicleControllerTask as `EVT_REMOTE_CMD` and the controller issues `SafeStop_Request(OPERATOR_STOP)` on the controller event path (Rev B section 9: "once validated it goes onto the controller's event path"). Network fault bits never call SafeStop. | FR23 | NEEDS TEAM INPUT (default: controller path, cause OPERATOR_STOP) |
| D-02 | Replay: repeated seq; START ignored for a guard period after every MQTT reconnect. | Broker re-delivers a retained or duplicated START frame after reconnect; the car could start without an operator present. | High (unexpected motion). | Command parser keeps `last_seq` and rejects equal seq; `START` additionally rejected while `comms_reconnect_guard_ms > 0` (T_REMOTE_START_GUARD, default 3000 ms, armed at every ONLINE entry and at boot). Does not change the 3-byte frame. | FR23, R7 | ACCEPT (safety, minimal) |
| D-03 | STOP_LATCH wording: plain byte store vs helper. | None functional; documentation ambiguity. | None. | `app_safe_stop_request()` performs a plain aligned byte store to `g_stop_latch` (step 1), then the write-if-NONE RMW of `stop_cause` through `app_shared_bits_*` (step 2), then `tk_set_flg` (step 3). Documented in `app_safety.c`. | - | ACCEPT (clarification only) |
| D-04 | MotionStatus spans two words without a common seq. | Reader can pair speed/distance from cycle N with motion_state from cycle N+1. | Low (both monotone), but STALE_MOTION detection needs a seq. | Use the 2 reserved bits of word A (30-31) and bits 3-4 of word B as a `cycle_tag`; a reader compares tags and re-reads on mismatch (bounded 2 attempts). Adopted field positions unchanged. | FR25 stale-motion detection | ACCEPT (uses reserved bits only; ratify) |
| D-05 | 8-bit ms event timestamp wraps every 256 ms. | Events buffered while offline lose absolute timing. | None. | Keep the adopted 4-byte record. TelemetryCommsTask tags every *flush* with the 32-bit snapshot time; the decoder unwraps the 8-bit stamp only within one flush and prints `t?` for records older than 256 ms. Alternative needing approval: 16-bit stamp in 16 ms units by shrinking payload to 8 bits. | FR20 (best effort) | DEFER (document) |
| D-06 | No heartbeat frame; 18-byte snapshot has no obstacle profile summary. | FR21 (heartbeat) and FR20 (obstacle scan results) cannot be shown complete. | None. | Two additional versioned frames on their own topics: `HB` 6 B (ver, seq, uptime_s u16, conn_state 2b + backoff 4b, dropped u8) every 1 s; `OBS` 10 B (ver, seq, ObstacleProfile word0, word1) on EVT_SCAN_DONE. The adopted 18-byte snapshot is untouched. Decoder + C/Python vectors included. | FR20, FR21 | ACCEPT (needed for FR20/21; ratify topics) |
| D-07 | MBF sizes may not include the per-message header. | A buffer sized 16 B holds 2 motion commands, not 4. | Medium (controller sends fail with TMO_POL -> rejected moves). | Measured: `HEADERSZ = sizeof(INT) = 4`, round-up to 4. `APP_MBF_BYTES(records, rec_size)` macro; MOTION 4 x 4 B = 32 B, TELEM 32 x 4 B = 256 B. | Correctness | ACCEPT (bug fix) |
| D-08 | Network IRQ vs barcode edge timing; network bits never stop the car. | Untested interference. | Low. | `fault_mask` bits WIFI_LOSS, BROKER_LOSS, TELEM_BUF_FULL are in the `APP_FAULT_DIAGNOSTIC_MASK`; `app_safe_stop_request` is never called from subsystem1. Interference measured in Phase 8 (A15). | NFR17 | ACCEPT (rule), measurement DEFERRED |
| D-09 | Integration owner unnamed. | Nobody signs off cross-task items A3, A13-A15. | Process. | `TEAM.md` has an explicit row; code review rule in `docs/TRACEABILITY.md`. | - | NEEDS TEAM INPUT |
| D-10 | (new, from the port audit) Rev B says TelemetryCommsTask owns the radio; TEAM.md forbids application tasks from touching cyw43/lwIP/MQTT, which run in the kernel service task. | A literal implementation would be rejected by the template rules and would call non-task-safe code. | Medium (radio stack corruption). | TelemetryCommsTask owns framing, connection bookkeeping (`comms_word`), command validation, queues and the 200 ms / 1 s cadence; `mqtt_utk.c` (shared library code, change agreed with the team/instructor per TEAM.md) polls `MBF_TELEM_OUT` with `TMO_POL` and publishes raw bytes, and pushes received bytes into `MBF_TELEM_IN`. Single network owner remains the kernel task; the application side never blocks. | NFR17, NFR26 | ACCEPT (port constraint; needs instructor agreement for the `mqtt_utk.c` change) |
| D-11 | (new) RemoteCmd "keeps the mutex" but is cmd 2b + seq 6b = 1 byte. | A mutex on a single byte adds an object and two kernel calls for nothing. | None. | Published as one aligned byte plus a generation byte, lock-free, under adopted rule (3) "a word <= 32 bits is published with one aligned store". | NFR28 | ACCEPT (rule 3 precedence; ratify) |
| D-12 | (new) ObstacleProfile bit sum. | Rev B says 49 bits; 9+6+6+7+7+9+3+3 = 50. | None. | Table corrected; positions fixed in `app_data.h`. | NFR28 | ACCEPT |
| D-13 | (new) Command frame bit order, command codes, CRC parameters, topics. | Decoder and firmware could disagree. | High if a malformed frame decodes as START. | Fixed in `app_telemetry.h`: byte1 = `cmd << 6 | seq`, codes 1 = START, 2 = STOP, 0/3 reserved-invalid; CRC-8 poly 0x07 init 0x00 no reflection xorout 0x00 over bytes 0-1; topics `is09/<id>/snap`, `/evt`, `/hb`, `/obs`, `/cmd`; retained inbound frames are rejected (lwIP MQTT exposes the retain flag only through the topic callback's `tot_len`... see Phase 6 for the actual mechanism used). | FR23 | NEEDS TEAM INPUT (values proposed, implemented) |
| D-14 | (new) `STALE_MOTION` as a stop cause. | Rev B lists 10 causes but names 9 + "stale ... motion data" in FR25. | - | Cause code 5 = STALE_MOTION. | FR25 | ACCEPT |
| D-16 | (new, Phase 3) TEAM.md left ADC ownership open: kernel `adca` device vs task-owned conversion. | Both subsystem3 and a kernel driver would otherwise claim the ADC. | Low. | `DEVCNF_USE_ADC 0` in `config/config_device.h` (a documented config switch); LineSensingTask owns the converter with a polled one-shot driver (`drv_line_adc.c`, ~2 us per conversion, bounded READY poll). | FR1, NFR3, NFR26 | ACCEPT |
| D-15 | (new) Robo Pico button polarity. | Datasheet gives pins, not polarity. | START misread as pressed could arm from S1 only; STOP misread is fail-safe. | Default: active-low with internal pull-up, `APP_CAL_BUTTON_ACTIVE_LOW = 1`; verified by HV-6 before any run. | FR24 | NEEDS TEAM INPUT (bench) |

## Documented deviations from BARR-C:2018 (NFR25)

| ID | Rule | Deviation | Justification |
|---|---|---|---|
| DEV-1 | 4.1.b (module names unique in first 8 chars) | `subsystem1.c` .. `subsystem5.c`, `subsystemN_test.c` | Names are mandated by the prescribed template (NFR26, `app_main.c` links `subsystemN_init/start/test`). |
| DEV-2 | 1.1 (C99) | Sources compile under the template's `-std=gnu11` | Kernel headers use GNU `Inline`/`Asm`; application code uses no C11/GNU feature except `_Static_assert` replaced by a C99 negative-array guard (`APP_STATIC_ASSERT`). Host tests compile with `-std=c99 -pedantic`. |
| DEV-3 | 4.2.a (one header per source) | `app_data.h` has no `.c`; `app_pack.h` is header-only inline | Pure definitions/inline helpers; documented. |
| DEV-4 | 3.1.j style vs template | Shared template files `app.h`/`app_main.c` are reformatted to the kit style when edited | Mixed styles inside one file are worse than reformatting a file the team already edits. Kernel/vendor files are never reformatted. |
| DEV-5 | 7.1.j (`g_` prefix) on kernel-mandated names | `tid_*`, `flg_*`, `mbf_*` object ID names follow the template's TEAM.md convention | Template convention; all are file-scope `static` where possible and `g_` is used for every other global. |
